# OxRefine 0.6.0

More ways to bring data into OxRefine, experimental storage for larger tables, better control over exports, and clearer workflows for recipes and reconciliation.

## New

- **MARC, wikitext and PC-Axis import.** Preview MARC/MARC-8 records, choose wikitext tables, or open PC-Axis data through the usual import view.
- **Database import.** Read SQLite, PostgreSQL, MySQL or MariaDB through a schema browser or a SELECT query. Preview the complete prepared result before creating a project; creation uses the snapshot without rerunning SQL. Saved profiles exclude passwords, and project metadata excludes SQL and credentials. Use a database account with read-only permissions.
- **Experimental row-code spilling.** Opt in with `OXREFINE_CODE_BUDGET_MIB` to move tracked row-code arrays to temporary mapped files. The budget covers those arrays; dictionaries, row indexes and operation scratch still need RAM. See [Importing](https://ilyaux.github.io/OxRefine/importing.html) for settings and scope.
- **Wikimedia Commons import.** Load files from categories with matched MediaInfo IDs, and optionally include file-page wikitext.
- **Language detection** using OpenRefine-compatible language profiles and behavior.
- **Customized exports.** Choose columns and their order, encoding, date and reconciliation output, and reuse saved settings.
- **MCP for assistants.** `ox mcp` connects a client to the same local server and saved projects, within the file paths you grant.
- **Review distinct values.** Transform previews and reconciliation results show value counts; candidates, scores and individual judgments are easier to inspect.

## Improved

- Browser pages select projects independently. Stale changes are rejected so another page cannot silently apply an edit to an outdated project view.
- Recipe errors identify the failing step, and a failed CLI run preserves an existing output file. Jobs show their stages, elapsed times and cancellation result.
- OpenRefine projects carrying unknown extension data preserve their original archive. Unsafe edited exports explain the limitation instead of silently dropping that data.
- JSON record-path selection, import controls, project management and facet interactions have been refined.

Compatibility is checked against real OpenRefine 3.10.1 outputs, with additional per-format reference fixtures. Wikitext imports table markup without rendering templates; MARC validation and other format-specific limits are documented in [Importing](https://ilyaux.github.io/OxRefine/importing.html) and [Differences](https://ilyaux.github.io/OxRefine/differences.html).

The experimental spill path completed a correctness workflow on 50,000,001 low-cardinality rows across 20 columns under a verified 1 GiB Linux cgroup limit with swap disabled. The kernel-reported cgroup peak was 1 GiB + 4 KiB, including charged file cache. Import, transformations, export validation, undo/redo, cancellation and restart/reopen passed for that dataset. This is a workload-specific result; it does not establish a universal memory limit or a speed comparison. See the [proof report](https://github.com/ilyaux/OxRefine/blob/main/benchmarks/out-of-core-baseline.json) and [measurement scope](https://github.com/ilyaux/OxRefine/blob/main/benchmarks/README.md).

Desktop build targets are Windows, macOS and Linux. Native command-line targets are Windows x64, Linux x64, Apple silicon and Intel macOS. Desktop installers are not OS code-signed; automatic updates require signed update artifacts.
