How this was measured
  • One Windows 11 laptop, both tools on 127.0.0.1, run one after the other. Every file size starts a fresh server process for each tool, so no run inherits a warm cache or JIT from another.
  • Data: a seeded generator of messy people records (7 columns: id, name, city, country, email, amount, signup) with case, whitespace, hyphen and accent variants. Larger files extend smaller ones row for row.
  • Both tools are driven through their own local HTTP API with the same steps: import with no type guessing, a list facet on country, fingerprint clusters on city, the same OpenRefine-format recipe JSON (collapse whitespace, trim, titlecase, mass-edit country, add a fingerprint column), then export all rows as CSV.
  • OpenRefine 3.10.1 runs with its bundled Java and the 1400 MB heap from refine.ini; its Windows .exe launcher would give it 1024 MB. OpenRefine receives the file as an upload while OxRefine reads it from disk, which adds a little to OpenRefine's import time.
  • Times are wall-clock from the client and include HTTP. Recipe time for OpenRefine waits until its background process queue is empty. Peak memory is the OS peak working set of the server process.
  • Single run per size, so small timings (under about 20 ms) are noisy. Reproduce with node benchmarks/compare.mjs in the OxRefine repository.
